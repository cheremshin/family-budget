# 0012. Две роли БД и выпуск образов по git SHA

Статус: принято, 2026-10-16

## Контекст

Приложение разворачивается в Docker, сначала локально, потом на отдельных машинах homelab. Нужно,
чтобы взлом веб-процесса не давал менять схему БД, а неудачный выпуск откатывался одной командой.

## Решение

- В БД две роли. `migrate` владеет схемой и запускает миграции, работает только в одноразовом
  контейнере `migrate`. `app` может только читать и писать строки, под ней работает приложение.
  Роли создаёт `docker/postgres/initdb/10-roles.sh`. Локально роль подставляет
  `scripts/with-db-env.sh`, поэтому команды с БД запускаются через `just`.
- Образы `web` и `migrate` тегируются коротким git SHA. `just prod-up` собирает образы, делает
  бэкап БД и поднимает новую версию; `just rollback <sha>` возвращает предыдущий образ `web`.
- Контейнеры работают на read-only файловой системе, без capabilities, с лимитами памяти; в проде Postgres
  доступен только во внутренней сети compose.

## Альтернативы

Одна роль-владелец для всего — проще, но процесс приложения сможет удалить таблицы. Тег `latest` —
неясно, что запущено, и откатываться не на что.

## Последствия

- Новые таблицы автоматически получают права для `app` через `ALTER DEFAULT PRIVILEGES`.
  Миграция, созданная не от `migrate`, этих прав не выдаст.
- Откат кода не откатывает миграции: миграции пишутся совместимыми с предыдущей версией кода.
