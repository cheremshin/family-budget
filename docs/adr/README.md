# ADR

Решения, которые дорого отменить и которые влияют на весь проект. Как писать код — в CLAUDE.md,
здесь — почему он устроен именно так.

Новое решение — новый файл со следующим номером. Если решение пересматривается, старый ADR не
переписывается: ему ставится статус «заменено ADR-NNNN». Формат: Контекст → Решение →
Альтернативы → Последствия → Пересмотреть, если.

Если код ещё не соответствует принятому решению, статус дополняется пометкой «не реализовано» или
«реализовано частично», а в конце ADR — раздел «Не реализовано»: что именно расходится и где.
Такой ADR описывает целевое устройство, а не текущее. Пометка снимается в коммите, который
устраняет расхождение.

В ADR не попадает то, что объясняется комментарием в коде или сообщением коммита: настройки
библиотек, раскладка папок, UX-мелочи.
