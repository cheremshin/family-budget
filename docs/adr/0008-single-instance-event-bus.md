# 0008. Шина событий в памяти процесса — приложение работает в одном экземпляре

Статус: принято, 2026-09-30

## Контекст

Событие об изменении бюджета (ADR-0007) публикуется в server action, а отдаёт его клиентам
SSE-хендлер. Это разные запросы, а в Next ещё и разные бандлы, поэтому им нужна общая шина.

## Решение

Шина в памяти процесса, хранится в `globalThis`, чтобы action и хендлер видели один объект. За
интерфейсом `MonthlyBudgetEventBus`, реализация — `InMemoryMonthlyBudgetEventBus`.

## Альтернативы

Postgres `LISTEN/NOTIFY` или Redis pub/sub. Для одной семьи на одном сервере это лишняя
инфраструктура.

## Последствия

Приложение должно работать ровно в одном экземпляре. На двух экземплярах синхронизация молча
сломается: событие с одного не дойдёт до клиентов другого. Ошибок при этом не будет.

## Пересмотреть, если

Понадобится второй экземпляр `web` (реплики, k3s, деплой без простоя). Замена — адаптер на
Postgres `LISTEN/NOTIFY` за тем же интерфейсом.
