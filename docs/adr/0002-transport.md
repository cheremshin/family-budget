# 0002. Чтение через GET, запись через Server Actions

Статус: принято, 2026-09-30

## Контекст

Next 16 отправляет Server Actions из браузера строго по одному: следующий ждёт, пока закончится
предыдущий (`node_modules/next/dist/docs/01-app/02-guides/server-actions.md`). Бюджет месяца
сначала читался через action. Из-за этого чтение вставало в очередь за сохранением, быстрое
листание месяцев копило запросы, а ушедший с экрана запрос нельзя было отменить.

## Решение

- Чтение — GET route handler в `app/api`, обёрнутый в `familyRoute`. Клиент ходит в него через
  `fetchJson` и передаёт `AbortSignal`, чтобы отменять устаревшие запросы.
- Запись — Server Actions через `familyActionClient`.
- Серверная предзагрузка страницы вызывает сервис напрямую, а не свой же GET.
- Оба транспорта приводят отказ к одному виду — `ClientError`. Чтение его бросает (на этом
  построены повторы TanStack Query), команда возвращает как `CommandResult` и не бросает никогда.
  Поэтому форма показывает ошибку у поля или над кнопкой, не закрывая диалог.
- Текст ошибки для пользователя пишет только сервер (`DomainError`). Всё остальное маскируется.

## Альтернативы

Оставить чтение на actions — очередь живёт в самом Next, обойти её нельзя. Перевести на route
handlers и запись — потеряли бы типизированный вход и ошибки валидации по полям, которые
next-safe-action даёт бесплатно; к тому же последовательная запись сохраняет порядок действий
пользователя.

## Последствия

- Чтения идут параллельно, не ждут сохранений и отменяются при смене месяца.
- Тип ответа GET не протягивается от сервера автоматически: его держит контракт из `domain`, а в
  dev ответ проверяет `assertContract`.
- Формат ошибки описан в двух местах — `familyRoute` и `handleServerError`, — и они должны
  совпадать.
