# 0007. Версия бюджета и живая синхронизация

Статус: принято, 2026-09-30. Реализовано частично — см. «Не реализовано».

## Контекст

Два участника работают с одним месяцем одновременно, часто с разных устройств. Каждый должен
видеть изменения другого без перезагрузки. Кроме того, Next при переходе «назад» может отдать
старые данные страницы, уже после того как во вкладке что-то сохранили.

## Решение

- У бюджета месяца есть `version`. Любое изменение бюджета, включая создание, увеличивает её на 1
  атомарно в той же транзакции и публикует событие.
- Событие уходит во все открытые вкладки семьи через SSE (`/api/family/monthly-budget/events`).
- На клиенте одно правило: из двух копий бюджета побеждает та, у которой `version` больше или
  равна. Его используют кэш, ответы команд, синхронизация и перенос данных из серверного рендера в
  браузер. Часы клиента и сервера не сравниваются.
- После переподключения SSE клиент перезапрашивает всё: за время разрыва события могли потеряться.

## Альтернативы

Периодический опрос сервера — задержка и лишние запросы. Сравнение по времени получения данных
(`dataUpdatedAt` в TanStack Query) — при отстающих часах клиента «назад» подставит старые данные
поверх свежего сохранения.

## Последствия

- `version` — признак свежести, а не защита от одновременной записи. Кто сохранил последним, тот и
  прав.
- Правило «больше или равна», а не «больше», потому что `version` не покрывает изменения в других
  модулях: категории, имена участников.
- Изменения категорий сейчас по вкладкам не рассылаются: второй участник увидит их при следующей
  загрузке.

## Не реализовано

Код пока расходится с решением, на него нельзя опираться как на факт:

- Увеличение не атомарно. `lib/monthly-budget/service.ts` читает бюджет и пишет
  `version: monthlyBudget.version + 1` без блокировки строки; две одновременные мутации запишут
  одну и ту же версию. Нужно `set version = version + 1` в SQL или `SELECT … FOR UPDATE`.
- Создание бюджета (`createMonthlyBudget`) не увеличивает `version` и не публикует событие:
  второй участник не видит новый месяц до следующей загрузки.
