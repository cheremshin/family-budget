# 0003. Состояние экрана — клиентская модель над кэшем запросов

Статус: принято, 2026-09-30

## Контекст

Экран бюджета — калькулятор. Пользователь выбирает участника и транш, правит план и сразу видит,
как меняется распределение, а второй участник в это время может менять те же данные. В первой
версии одно состояние было размазано по четырём сторам, проверки «данные загружены» и
блокировки дублировались, и каждый виджет держал собственную ветку загрузки.

## Решение

Цепочка Model → Snapshot → VM → View на MobX:

- данные сервера живут только в кэше TanStack Query и в модель не копируются;
- модель фичи — один стор, в котором лежит только выбор пользователя (участник, транш);
- снимок (snapshot) — вычисляемое значение: данные, выбор, текущий пользователь, блокировки,
  распределение;
- VM виджета не хранит состояния, она строит view из снимка и даёт намерения;
- запрет считается в снимке один раз: view заранее объясняет его пользователю, VM возвращает его
  без похода на сервер.

Структура файлов — в CLAUDE.md.

## Альтернативы

- Server-first: данные и разметка в серверных компонентах, actions с `refresh()`, без клиентской
  модели. Предпросмотр распределения до сохранения всё равно вернул бы расчёт на клиент, каждая
  смена месяца и каждое сохранение стали бы походом на сервер, а `router.refresh()` поверх
  открытой формы рискует потерять ввод.
- React-хуки с DI на портах без MobX. Выбор участника, блокировки и распределение — один граф
  зависимостей, и на хуках он превращается в цепочку `useMemo` с ручными зависимостями.

## Последствия

- Смена закэшированного месяца и пересчёт происходят мгновенно, без сервера.
- Снимок нельзя рассинхронизировать с кэшем: копии данных нет.
- Три реактивные системы сразу (React, MobX, кэш запросов) — высокий порог входа.
- Периферийные экраны без расчётов (настройки, категории) так делать не обязательно — там хватает
  серверного компонента и формы.

## Пересмотреть, если

Появится состояние со своим жизненным циклом (например, черновик распределения) — тогда нужен
второй стор.
