# 0005. Жизненный цикл клиентских объектов без `destroy`

Статус: предложено, 2026-09-30. Принять после проверки (см. ниже).

## Контекст

React не различает «компонент скрыт» и «компонент удалён навсегда». StrictMode в dev монтирует
эффект дважды, а `<Activity>` при скрытии страницы вызывает cleanup и сохраняет состояние. Раньше
граф фичи уничтожался в cleanup, и после повторного показа экран больше не обновлялся.

## Решение

- Создание объектов чистое: без подписок, таймеров и сетевых соединений. Если React создаст лишний
  экземпляр, его просто соберёт сборщик мусора.
- Внешние ресурсы включаются в `activate()` из `useEffect` и выключаются в его cleanup. Сейчас
  такой ресурс один — SSE-соединение, у него счётчик подписчиков.
- Явного уничтожения нет. Запросы и команды ленивые: они подписаны на кэш, только пока их кто-то
  наблюдает.

## Альтернативы

Уничтожать с задержкой (`setTimeout`) и отменять при повторной активации. Это спасает от
StrictMode, но не от `<Activity>`: скрытие может длиться сколько угодно.

## Что не проверено

Ленивые команды (`Mutation` с `lazy: true`) должны работать без наблюдателя и не удерживаться в
памяти после ухода со страницы. Для запросов это проверено, для команд — нет. Проверка: скрипт с
`QueryClient` и `Mutation`, затем heap snapshot после 20 переходов туда и обратно.

## Пересмотреть, если

Проверка покажет утечку. Тогда scope получает `AbortController`, а `abort()` вызывается
отложенно, с отменой при следующей активации.
