# Правила бюджета месяца

Как должно работать приложение с точки зрения пользователя. Расчёт распределения — в
[distribution.md](distribution.md).

## Семья

- Семью создаёт владелец, второй участник присоединяется по коду-приглашению.
- Число участников ограничено `maxMembers` семьи.
- Число участников меняет только владелец. Остальные настройки (название, способ деления,
  политика личного остатка) меняет любой участник: пока настройки — единственное место, где можно
  попробовать другой способ деления на открытом месяце.
- Политика личного остатка по умолчанию `equalized`. Формы выбора пока нет.

## Месяц

- Бюджет создаётся на месяц явно, кнопкой «Создать». Открывать можно любой месяц, в том числе
  будущий: если бюджета нет, показываем карточку «нет записей» с этой кнопкой.
- Открытый месяц всегда отражает текущие категории семьи: новая категория сразу в нём появляется,
  изменённая — меняется, архивная — пропадает.
- Каждый участник сам задаёт свой плановый доход. Ноль — допустимый план.
- Поступление (транш) участник записывает только себе и только после того, как задал план.
- Все изменения месяца, включая его создание, видны второму участнику сразу, без перезагрузки.

## Закрытие месяца

- Закрыть месяц может только владелец семьи, и только если:
    - у каждого участника задан план;
    - в месяце есть хотя бы одна категория;
    - категории не требуют больше, чем планы участников (нет перерасхода).
- Если закрыть нельзя, кнопка неактивна и причина видна заранее, а не приходит ошибкой после
  нажатия (не реализовано, см. ниже).
- Закрытие необратимо, поэтому интерфейс спрашивает подтверждение.
- При закрытии сохраняются состав категорий, способ деления, политика остатка и итог
  распределения. Дальнейшие изменения настроек и категорий семьи закрытый месяц не затрагивают.
- В закрытом месяце нельзя менять план и состав категорий. Поступления записывать можно: деньги
  приходят и после конца месяца.

## Не реализовано

Код пока расходится с правилами выше. План — [domain-migration.md](../domain-migration.md).

- **Кнопка закрытия.** При любой причине отказа она скрыта, а не неактивна с объяснением.
  Клиентская проверка (`features/monthly-budget/model/locks.ts`, `closeBlockerOf`) не знает про
  пустой состав и перерасход: в этих случаях кнопка видна, а сервер отвечает ошибкой.
- **Инвариант категории обходится при изменении**: частичное обновление проверяет только
  присланные поля, сервис итоговое состояние не проверяет. Смена режима без суммы проходит молча
  (10% становятся 10 ₽), фиксированная сумма 0 разрешена и схемой, и CHECK в БД. Процент больше 100
  отклоняет только CHECK, и пользователь видит «Не удалось выполнить операцию» вместо причины.
